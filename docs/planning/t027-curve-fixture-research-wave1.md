## Source facts that constrain the oracle

- **Pitch curve units/shapes:** x is note-local milliseconds and y is tenths of a semitone; supported per-point shapes are io, l, i, o, sp. The editor normalizes authored curves to note anchors, but display can retain imported pre-onset points. It samples at 5 ticks, has a 2,000-point cap, enforces strictly increasing x, and clamps freeform y to ±120 tenths. See [pitch-curve-input.js:6–20](ui-mock/react-dock/src/openutau/pitch-curve-input.js#L6-L20), [pitch-curve-input.js:47–95](ui-mock/react-dock/src/openutau/pitch-curve-input.js#L47-L95), [pitch-curve-input.js:123–158](ui-mock/react-dock/src/openutau/pitch-curve-input.js#L123-L158), [pitch-curve-input.js:171–207](ui-mock/react-dock/src/openutau/pitch-curve-input.js#L171-L207), and [pitch-curve-input.js:248–333](ui-mock/react-dock/src/openutau/pitch-curve-input.js#L248-L333).
- **Interpolation:** for a 0→100 segment, midpoint values from the UI formulas are 50 for l/io, about 29.29 for i, and about 70.71 for o. Rust evaluates pitch on a 5-tick grid and uses these shapes through interpolate_shape; sp is used only with more than two points and a non-auto-completed next point. The Rust and OpenUtau reference CubicSplineSegment are Catmull–Rom and weight tangents by actual neighboring x distances; the UI sp formula uses uniform-parameter Catmull–Rom. They coincide for evenly spaced knots but may diverge between irregularly spaced knots. Test irregular sp interiors against Rust output, not the UI formula as an exact oracle; knot values should remain exact. See [pitch.rs:21–60](native/crates/feed/src/pitch.rs#L21-L60), [pitch.rs:291–324](native/crates/feed/src/pitch.rs#L291-L324), [SplineInterpolate.cs:8–32](ref-openutau-clean/core/OpenUtau.Core/Util/SplineInterpolate.cs#L8-L32), and [pitch-curve-input.js:166–203](ui-mock/react-dock/src/openutau/pitch-curve-input.js#L166-L203). Existing engine spline coverage uses four knots and checks bounded peak/overshoot in [pitch.rs:462–485](native/crates/feed/src/pitch.rs#L462-L485).
- **Expression curves:** UCurve has xs/ys/abbr and no per-point shape. Samples are linear between stored points; outside their range sample() yields None and the feed uses the descriptor default. The feed samples each 5 ticks, then linearly resamples/clamps per frame. Existing examples are [curve.rs:23–88](native/crates/feed/src/curve.rs#L23-L88), [curve.rs:102–126](native/crates/feed/src/curve.rs#L102-L126), and [domain/curve.rs:3–61](native/crates/domain/src/curve.rs#L3-L61).
- **Canonicalization/undo:** stroke commits snap to a 5-tick grid, merge/collapse points, add descriptor-default interval boundaries and simplify with min(5, (max-min)*0.005). Reference RDP behavior is in [ExpCommands.cs:327–375](ref-openutau-clean/core/OpenUtau.Core/Commands/ExpCommands.cs#L327-L375); native examples are in [session_curves.rs:94–128](native/crates/project-session/tests/session_curves.rs#L94-L128) and [session_curves.rs:251–297](native/crates/project-session/tests/session_curves.rs#L251-L297).
- **Scale and preview wiring:** expression lane and piano-roll pitch mapping use the shared configured ROLL.beatWidth, so equal-scale landmarks can be specified in ticks; this is a designable visual comparison, not measured parity. See [expression-lanes-panel.jsx:79–83](ui-mock/react-dock/src/openutau/expression-lanes-panel.jsx#L79-L83) and [piano-roll-panel.jsx:169–197](ui-mock/react-dock/src/openutau/piano-roll-panel.jsx#L169-L197). Expression stroke move calls onStrokeEnd(null, samples) but the parent handler accepts only samples; the null first argument clears stroke state. On pointer-up the samples are then set, committed, and cleared immediately, so the current lane has no independent transient preview. See [expression-lanes-panel.jsx:115–125](ui-mock/react-dock/src/openutau/expression-lanes-panel.jsx#L115-L125) and [expression-lanes-panel.jsx:316–330](ui-mock/react-dock/src/openutau/expression-lanes-panel.jsx#L316-L330). Pitch edits send note/pitch through grouped session updates during pointer moves; release closes the engine transaction, so UI isolation must be checked at the committed projection boundary rather than assumed from gesture grouping. See [piano-roll-panel.jsx:390–395](ui-mock/react-dock/src/openutau/piano-roll-panel.jsx#L390-L395), [piano-roll-panel.jsx:562–575](ui-mock/react-dock/src/openutau/piano-roll-panel.jsx#L562-L575), and [clone-state.jsx:621–644](ui-mock/react-dock/src/openutau/clone-state.jsx#L621-L644).
- **Descriptor context:** curve_stroke_context_json returns a revision-tagged curve/base plus descriptor min, max, custom default and simplify tolerance; it resolves one existing curve, not a lane list. UExpressionDescriptor has metadata such as name/abbr/type/bounds/default/options, but no color field. The current panel takes tabs, labels, bounds/default and colors from static EXPRESSION_LANES mock data. See [session.rs:997–1046](native/crates/project-session/src/session.rs#L997-L1046), [expression.rs:126–174](native/crates/domain/src/expression.rs#L126-L174), [expression-lanes-panel.jsx:339–359](ui-mock/react-dock/src/openutau/expression-lanes-panel.jsx#L339-L359), and [mock-data.js:49–60](ui-mock/react-dock/src/openutau/mock-data.js#L49-L60).

## Work partition and blockers

**Testable on existing Rust authority after implementation is authorized:** interpolation and endpoint behavior, sparse/default values, canonical stroke output, dense simplification, one-revision/undo and stale expected-revision conflict. Existing coverage means a future test should target a gap (not duplicate current assertions). This task did not create or run tests.

**Descriptor/API/UI gated:** Rust-backed expression lane list and descriptor-driven tabs/labels/colors, equal-zoom rendered comparison, UI preview-vs-committed isolation, and end-to-end stale-base handling. The lane list/color are currently static; the per-curve context does not supply a lane catalog/color. T014 review is the stated gate; T009 owns stroke transport/rebase, and T026/T027 share piano-roll integration ownership. No existing UI files were changed and no fixtures/tests/builds or Git operations were performed.
