# T050 — Incremental phoneme preparation into WORLD streaming

**Status:** done  
**Owner:** Codex / Antigravity  
**Last updated (UTC):** 2026-11-11T14:08:23Z

## Goal

Prototype and integrate a bounded producer–consumer pipeline: preparation/render workers keep later work moving while the audio/mix consumer emits finalized PCM as soon as it is safe. Keep PCM identical to the whole-phrase baseline, bound memory/backpressure, and measure first PCM and full render time on the actual `.rustx` project.

### Execution model to validate

- Parallelize independent tracks/phrases as renderer jobs where their source context is self-contained; deliver each job's PCM blocks to a timeline mixer.
- Within one WORLD phrase, phoneme/model preparation is parallel, but results must be committed in stable timeline/request order. The synthesis cursor consumes only the contiguous finalized timeline prefix plus required lookahead.
- Target topology clarified by user: **one synth worker plus one or two concurrent preparation workers**. Do not count a pool of 1/2/4 prep workers followed by synthesis as equivalent evidence.
- A bounded queue and shared worker budget prevent unbounded prepared-model memory or oversubscription. The audio consumer waits only when the next required PCM range is not ready, not for an entire project/phrase render.
- Preserve a serial/full-render fallback and exact parity for export.
