## Goal

Make the selected OpenUtau phonemizer in a USTX track execute end to end for the primary Web + local Rust server host. Rust remains authoritative for project/session state, validation, undo, render planning, and audio rendering. A managed host may derive the selected plugin's phonemes from an immutable Rust snapshot and return a bounded, versioned result that Rust validates and consumes. This task targets the official `OpenUtau.Plugin.Builtin.JapanesePresampPhonemizer` first; arbitrary third-party DLLs are not implied.

Android remains deferred. Direct-WASM must report the plugin unavailable until it has an approved managed-host bridge; it must not silently claim parity or substitute a different phonemizer.

## TTFS / midchunk-stream constraint (2026-10-15T14:43:35Z)

- Confirmed the user's latency concern in the current code: `PhraseRenderer::render_phrase` returns a complete `Vec<f32>`; both offline and streaming paths call it synchronously and only then pass samples to the block mixer/WebSocket sink. WebSocket's 2048/4096-frame blocks are transport framing, not incremental synthesis.
- Therefore, raising `CHUNK_TARGET_MS` to 30 s changes the maximum audio-duration unit that must finish before its first PCM can be mixed. It does **not** imply 30 seconds of wall-clock compute, but a longer first phrase can increase time-to-first-vocal versus 4 s chunks. Media at timeline 0 can still play before the first voice chunk is ready.
- A real midchunk stream requires a renderer API that yields completed PCM blocks while preserving phrase-level timing/curves and synthesis continuity across blocks. For WORLD this means moving below `WorldlineRenderer::render_phrase`/`PhraseSynth::synth`'s whole-vector API; simply forwarding smaller WebSocket frames cannot solve the latency.
- Keep the 30 s setting as a measured quality mitigation for the current fixture, with the latency tradeoff explicit. Next implementation step is to design a callback/iterator renderer and prove it matches whole-phrase output while making the first block available before the phrase completes; then the plan can return to short chunks without reintroducing independently restarted mid-phrase synthesis.
